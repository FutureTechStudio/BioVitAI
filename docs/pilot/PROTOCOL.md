# BiovitAI local synthetic pilot protocol v1

Scope: English web and Android rehearsal in a loopback-only environment using synthetic reports and adult test accounts. UAE and India are intended markets, not approved production hosting jurisdictions. iOS source configuration is included; Apple build and device validation require a suitable environment. Reviewer appointment remains deferred. No unreviewed conversion, clinical interpretation, aggregation or organ score is enabled.

Participation is voluntary. Explain which synthetic data is stored, local encryption, family access grants, and optional external AI processing before starting. The profile owner must explicitly grant health AI consent. Withdrawing consent stops later AI retrieval and dispatch. It does not recall data already processed by a provider. Server credentials, a model and current pricing must be configured before live calls. OpenAI requests use `store:false`; this is not a claim of zero provider retention.

Participant instructions:

1. Create and verify a synthetic account using the private local mailbox. Create a family member without an email, select it, and confirm the profile indicator.
2. Upload a controlled report. Observe scan/extraction states. Open the source page, confirm identity explicitly, and check every result before verification. Correct one result with a reason. Confirm the original extraction and correction history remain visible.
3. Upload a second report. Explain each trend exclusion. Inspect both sources; separate laboratory results must never be averaged. Organ states remain not assessed without approved rules.
4. Grant optional AI consent. Ask about verified evidence. Follow a citation, withdraw consent, and verify that another request is denied. Unconfigured or unavailable providers must show unavailable states.
5. Switch family profiles during a delayed request. No prior profile result or conversation may remain visible. Exercise viewer and caregiver grants, then revoke access.
6. Test scanner outage, malformed input, worker interruption, stale corrections, budget exhaustion, and isolated backup restoration using synthetic fixtures.

Acceptance: no cross-profile disclosure, silent identity match, unverified clinical publication, fabricated accepted citation, automatic result averaging, exceeded reserved budget or lost evidence. All displayed results need report/page/revision provenance. Engineering severity 1/2 defects must be resolved before a participant session is authorized.

Severity 1: private-data disclosure, authorization bypass, lost or corrupted originals, wrong-person merge, uncontrolled external disclosure or budget bypass. Stop the affected flow and preserve scrubbed evidence.

Severity 2: wrong displayed value/provenance, stale evidence accepted, broken verification/revocation, inaccessible critical journey, failed restore or materially misleading AI output. Block readiness until fixed and regression-tested.

Severity 3: noncritical usability or recoverable reliability issue. Severity 4: cosmetic or documentation issue. Every defect records synthetic reproduction, affected version, impact, owner, resolution and verification.

Interview prompts: Which profile did you believe you were viewing? Could you identify the source of each value? Which exclusions were unclear? Was consent understandable? Could you recover from a failure? Which task was hardest? Do not ask for real medical history.

Record feedback only in FEEDBACK.md when supplied by an actual participant. Automated rehearsals are engineering evidence, not human research. Participant consent, attendance, qualitative findings, clinical review and pilot signoff remain pending until documented by the responsible humans.
